# Spec — stand up cherokeelessons.org on Cloudflare Workers (Static Assets)

Remote issue: https://github.com/CherokeeLanguage/CherokeeLessons/issues/31

## Problem

`cherokeelessons.org` — the site's canonical domain — has **no origin**: the apex has no A/AAAA record (probed live 2026-11-11: "Could not resolve host"), the VPS that served it is gone (established by the developer), and the working redirect chain dead-ends there: `cherokeelessons.com` (+www) serves a Cloudflare 301 → cherokeelessons.org (path-preserving, working — `server: cloudflare`, verified by HTTP probe), and `www.cherokeelessons.org` 301s to the apex (working) — into nothing. The Apache-era publish path (`publish.sh`: omen-desktop hostname gate + rsync to `vhost.cherokeelessons.com` — a name with no public DNS record — plus `.htaccess` copying) is dead code. The executed stand-up gate (2026-11-11: shallow clone of trunk `789a7f8` + `./build.sh` → exit 0, 1,547 files / 0.48 GiB; `research/standup-gate-build.log` for the build output, work-record gate section for the counts) proves the tracked tree builds cleanly. This spec stands the site up on **Cloudflare Workers Static Assets** — the platform Cloudflare recommends for new static sites (verified live 2026-11-11 against the Pages landing banner "Start new projects with Workers"; Pages itself not deprecated but legacy) — so that a merge to the production branch automatically redeploys cherokeelessons.org (Workers Builds runs build → deploy on every push to the production branch; PRs get preview builds — verified).

## Requirements

- **R-1 — Assets-only deployment manifest.** A tracked `wrangler.jsonc` SHALL declare `"name": "cherokeelessons-org"`, a `compatibility_date`, `"assets": { "directory": "./public", "not_found_handling": "404-page" }`, and a `"previews": {}` block (wrangler 4.153.0 hard-errors on PR preview builds without it — observed on the sibling 2026-10-27; re-verify at implementation). No Worker script, no bindings — the built `public/` is the deploy unit.
- **R-2 — Branch-aware build.** `build.sh` SHALL gain production/preview base-url logic: branch from `WORKERS_CI_BRANCH` with a git fallback; production (the repo’s branch of record, `master` — verified via `git ls-remote --symref origin HEAD`) builds with the base_url of record; non-production builds are domain-neutral (`--base-url /`) so any preview hostname serves correctly; an explicit `SITE_BASE_URL` override wins in both modes. The existing pin-download-and-build core (issue #28's delivered mechanism) is unchanged.
- **R-3 — Base URL of record.** `config.toml` SHALL carry `base_url = "https://cherokeelessons.org/"`.
- **R-4 — Lemmatizer item whole: redirect + retirement.** A tracked `static/_redirects` SHALL carry exactly: `/CherokeeLemmatizerGwt* https://cherokeedictionary.net/CherokeeAnalyzer/#!Analyzer 302` — written in the documented `_redirects` format — unquoted target; the docs’ own fragment example is unquoted, comments are only lines starting with `#`, and destinations can include fragments (verified against the redirects doc 2026-11-11). Behavioral verification: `curl -I` on the deployed host shows `Location` carrying `#!Analyzer`. This is the only redirect entry: the legacy `.htaccess` table is discarded (developer decision), and issue #30's itch targets are page-level links, not redirects.
- **R-5 — `_headers` derived from this site's actual embeds.** A tracked `static/_headers` SHALL set at minimum `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, and a Content-Security-Policy derived from the site's real third-party usage — `giscus.app` (comment system, `templates/page.html`), YouTube (post-#30 embeds), and `'self'` — and SHALL NOT carry origins transplanted from other sites (the sibling's CSP lists hyvor/vimeo and would break giscus). The CSP's final form is verified at plan time by observing the built pages' actual network requests.
- **R-6 — Apache-era publish path retired.** `publish.sh` and `content/.htaccess` SHALL be deleted; `README.md` SHALL document the new deploy path (merge to `master` → Workers Builds → `npx wrangler deploy`; PR previews via `npx wrangler preview`) and the ops sequence (GitHub App connection; Worker creation with the manifest’s name `cherokeelessons-org` (name-match is a builds-fail condition); build command configured to `./build.sh` — unset means no build runs and the Wrangler config is not consulted for it; production-branch selection set to `master` — the builds default is `main`; custom-domain attachment for apex and www; R2 bucket + public delivery), and SHALL NOT continue documenting the retired publish path (the existing paragraph describing `./publish.sh` and the rsync to the vhost host is removed — the change makes it false).
- **R-7 — Deterministic deploys.** A tracked `package.json` SHALL pin wrangler via a `wrangler` entry with an exact version (Workers Builds uses the wrangler version set in the repo’s `package.json` — verified against the configuration docs), eliminating the unpinned-wrangler drift class that produced the previews-block quirk.
- **R-8 — Oversized PDFs out of the assets surface.** The two tracked book PDFs over the 25 MiB/file limit (`static/pdf-downloads/Na_Kanoheda_Kwiti_Jisdu-embedded-cover.pdf` 70.1 MiB, `static/pdf-downloads/Cherokee-Language-Lessons-Volume-I-embedded-cover.pdf` 36.5 MiB) SHALL be relocated to a tracked, non-served directory, and the two book pages' download links SHALL point at their R2 delivery URLs (ops prerequisite: R2 bucket with public delivery, recorded at plan time). The files stay tracked as sources of record; the artifacts ship unchanged. Alternatives weighed: re-compression alters the published artifacts; itch-as-book-downloads was not requested.

## Approach

Follow the verified modern pattern: assets-only Workers (no script, no bindings) with Workers Builds push-to-deploy — the developer's explicit direction, with PR-merge auto-redeploy confirmed against the platform docs. The sibling `brothertown-language-com` is the structural precedent; `michael-conrad.com` — itself migrated to the same assets-only pattern on 2026-11-11 — as the second precedent; per the no-cargo-culting rule every carried element is justified by this repo's own surfaces (base_url fix, giscus-derived CSP, no cache table, no zola.toml rename). Alternatives weighed: Cloudflare Pages — rejected (legacy platform; CF recommends Workers for new projects); a custom Worker script for redirects — rejected (unnecessary: `_redirects` covers the one needed rule; assets-only stays simpler); R2 for all large media — rejected (after #30 only the two PDFs exceed the limit; the media classes move to YouTube/itch); re-compressing the two PDFs — rejected (alters the published artifacts).

## Impact

Consumers: cherokeelessons.org (unresolvable → serving the site; the existing `.com`→`.org` and `www`→apex rules light up unchanged); every merge to `master` (automatic build+deploy; PR preview URLs); the publish workflow (the `publish.sh`/omen-desktop/`.htaccess` era ends); the two books' download links (R2 delivery, artifacts unchanged). Risk concentrates in R-2/R-3 (URL generation) — mitigated by the executed gate plus SC-3/SC-9's fresh-build instruments and R-2's domain-neutral preview mode. Rollback: revert the commit set (Worker/custom-domain attachments are dashboard-reversible; the custom-domain DNS records are auto-managed). Stated precondition: the Cloudflare-side ops sequence must complete before the first production deploy; the repo-side changes are independently verifiable via the fresh-clone build and dry-run instruments.
