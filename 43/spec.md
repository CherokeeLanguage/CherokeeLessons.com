## Requirements

- **R-1** — The wiki page `Ebook delivery runbook` SHALL document the delivery operation set, agent-managed via the `ia` CLI, with these element sets, each checkable:
  1. **Prerequisites** — an archive.org account; IA S3 keys generated at the account's settings page and installed with `ia configure` — the config lands at `$XDG_CONFIG_HOME/internetarchive/ia.ini` by default (`$HOME/.config/internetarchive/ia.ini` when `$XDG_CONFIG_HOME` is unset; the legacy locations `$HOME/.config/ia.ini` and `$HOME/.ia` are checked for compatibility only, never written — per the Configuration reference); alternatively the `IA_ACCESS_KEY_ID` / `IA_SECRET_ACCESS_KEY` environment variables (both must be set together). Credential custody — keys never committed to the repo or echoed into transcripts.
  2. **Item stand-up** — per-book items whose metadata pairs of record are tracked in item-definition files beside the PDFs (`book-sources/pdf-downloads/`); upload via `ia upload <identifier> <pdf> --metadata='mediatype:texts' --metadata='title:…' …`, each metadata pair passed as a repeatable `--metadata='KEY:VALUE'` argument — the mediatype MUST be set at upload time (items otherwise upload with a `data` mediatype that cannot be changed afterwards, per the CLI reference's Upload warning), and items default to the opensource (Community Texts) collection; bulk metadata updates go through `ia metadata --spreadsheet=<csv>` (identifier column required, one item per row, UTF-8); identifier rules: 5–80 characters, unique across archive.org, lowercase letters/numbers/dashes/underscores preferred, no special characters (collisions append year-month).
  3. **Recurring operations** — metadata edits via the `ia metadata` command family (the CLI reference's Metadata section documents `--append-list`, `--remove`, and the bulk `--spreadsheet=<csv>` path); file addition via `ia upload <identifier> <file> …`; file deletion via `ia delete <identifier> <file>` (deletions are backed up under the item's `history/files/` unless `-H x-archive-keep-old-version:0` suppresses the backup); file replacement as delete-then-upload using those verified forms; metadata edits go through the CLI (the uploading-tips constraint that non-ASCII typed into upload forms breaks the item's XML is cited); every operation closes with its verification line.
  4. **Account model and shared maintenance** — the account model of record: a single dedicated account for the ebook items (the IA-recognized organization pattern — Community Webs guidance "one account per org: simple setup/maintenance"); whoever operates holds that account's S3 keys; item administration belongs to the uploading account (the item page's add/edit/delete flows are the item admin's); admin-granting beyond the uploader is a collection-level mechanism — collections can have multiple admins, nominated by email to IA, with edit rights over all items in that collection; a custom collection is requestable at a 50-item minimum, and until then uploads default to the Community Texts collection; before a custom collection exists, shared maintenance runs on key custody of the account of record; IA's Vault — IA's digital repository and preservation service for organizations, with its own account administration surface — is a separate product class outside this runbook's free-CLI path.
  5. **Verification set** — every operation closes with its checks: the direct-download URL responds 200 with Content-Length equal to the tracked file's byte length (byte-identical comparison in full available via `ia download`); the item page resolves; the metadata renders with the syllabary intact; task progress and logs are observable via `ia tasks` (including `--follow-task-log`); file listings via `ia list <identifier>`.
- **R-2** — The runbook SHALL state the disposition of record and its boundaries: archive.org via agent-managed `ia` CLI is the cherokeelessons ebook delivery path; delivery URLs take the form `https://archive.org/download/<identifier>/<file>`; the artifacts ship unchanged from the tracked sources (`book-sources/pdf-downloads/` is the source of record); R2 and the `files.cherokeelessons.org` subdomain are permanently excluded per the ruling of record (AGENTS.md cross-reference).
- **R-3** — The runbook SHALL record the Cherokee-syllabary metadata handling and the verification posture: syllabary/Osage text in title/description goes through the CLI's UTF-8 metadata path; the first item's rendered metadata and download are inspected before the pattern is reused for further items; item-page surfaces (reader/search) refresh at IA's documented derive pace (uploads derive in "a few seconds, hours or sometimes days"; file edits trigger a derive task about 15 minutes later); each operation's availability is settled by its verification line from R-1.5 — a failing check is re-checked after the documented derive intervals, and persistent failure escalates to IA (info@archive.org) rather than being assumed away.
